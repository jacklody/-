# 智能日历助手 v4.0 协作审批版 — 设计文档

日期：2026-09-21
分支：`feature/collab-approval-v4`
基线：main 分支的智能日历助手 v3.0（单文件 HTML + localStorage）

## 一、目标与范围

在现有纯前端单文件 HTML 日历助手基础上，新增以下能力：

1. **@提及系统**：新建待办时支持 @单个成员、@群组、@所有人；@后通过飞书 Webhook 向群发送通知消息并 @对应成员触发其飞书消息弹窗；点击消息可跳转回日历助手并定位到对应 @处。
2. **成果资料上传**：待办完成/提交时上传交付成果，支持图片（所有格式）、PDF、Word、Excel、PPT、Markdown、txt，Base64 存入 localStorage。
3. **部门经理审批流**：待办由负责人完成后流转到其直属部门经理审批；经理可通过或驳回；驳回时需填写新的完成日期和新增要求批注。
4. **多维筛选排序**：按人（负责人）、按节点（审批状态）、按职能筛选，支持多种排序。
5. **飞书深度联动**：通过群机器人 Webhook 发消息卡片（含飞书日历创建深链+回跳日历助手深链），无需后端即可实现跨端提醒。

**不包含**：真实后端存储、飞书 OAuth 登录、飞书文件云存储、跨设备实时同步（纯前端 localStorage 单设备方案）。

## 二、整体架构

保持零依赖单文件 HTML 架构。所有新增逻辑内联在 `智能日历助手.html` 中。

│  └──────────┘ └──────────┘ └──────────┘ └────────┘ │
│  ┌──────────┐ ┌──────────┐ ┌──────────┐ ┌────────┐ │

## 四、功能模块详细设计

### 4.1 @提及系统

**输入体验**：
- 新建/编辑待办弹窗的「描述」输入框和「负责人」区域支持 `@` 触发联想下拉
- 输入 `@` 后显示下拉列表：① `@所有人` 选项在最顶部；② 最近使用成员；③ 按输入关键字过滤成员和群组
- 键盘上下选择，Enter/Tab 确认
- 群组被选中后，通知时展开为群内所有成员
- 选中后输入框内显示为蓝色标签块（类似飞书 @样式），底层数据以 `@[memberId]` 标记语法存储（如 `请@[m_001]协助@[g_001]`），渲染时解析

**负责人选择区**：
- 弹窗底部独立区域「👥 负责人」，显示已选成员头像+姓名标签，可点×移除
- 快捷按钮：「@所有人」「选择群组」
- 被选中的成员自动成为待办 `assignees`

**展示**：
- 待办列表项右侧显示负责人头像组（最多显示 3 个，更多显示 +N）
- 待办详情中 @姓名高亮为蓝色，hover 显示成员所属部门/职能
- 当前用户（在设置中"当前身份"下拉选择的成员）被@的待办在列表中以左边界彩色条标记

**@所有人**：
- 设置 `mentionAll: true`，通知时展开为 members 列表中除创建者外所有人
- 待办卡片显示 `@所有人` 红色标签

### 4.2 飞书 Webhook 通知集成

#### 4.2.1 配置面板（「⚙️ 设置 → 飞书集成」）

**配置项**：

| 字段 | 说明 | 是否必填 |
|------|------|---------|
| 群机器人 Webhook URL | 飞书群自定义机器人的 webhook 地址 | 是（全局默认） |
| Webhook 签名密钥 | 机器人签名校验 secret，安全校验用 | 推荐 |
| 日历助手访问地址 | 部署后访问本助手的 URL（用于消息卡片回跳链接）；本地双击打开时自动填 `file://` 路径，但建议部署到 http(s) 以支持飞书内直接打开 | 推荐 |
| 当前身份 | 下拉选择「我是哪个成员」，用于识别"我的待办/待我审批" | 是 |

**群组级 Webhook 覆盖**：
- 在「群组管理」中可为每个群组单独配置 Webhook URL，通知该群组待办时发到该群；未配置则使用全局默认。

**测试按钮**：
- 面板内提供「发送测试消息」按钮，验证 Webhook 是否配置正确。

#### 4.2.2 用户配置指引（内置在设置面板中）

设置面板顶部折叠式指引区「📖 如何获取 Webhook？」，点击展开图文步骤：

**步骤 1：创建飞书群自定义机器人**
1. 打开飞书，进入需要接收通知的群聊（或新建一个"日历助手通知群"）
2. 点击群右上角「⋯」→「设置」→「群机器人」→「添加机器人」
3. 选择「自定义机器人」
4. 填写机器人名称：建议填「日历助手」；上传头像（可选）
5. （推荐）安全设置勾选「签名校验」，复制生成的 Sign Secret
6. 点击「添加」，复制生成的 **Webhook 地址**
   - 地址格式：`https://open.feishu.cn/open-apis/bot/v2/hook/xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx`

**步骤 2：填入本面板**
- 将 Webhook 地址粘贴到「群机器人 Webhook URL」
- 若开启了签名校验，将 Sign Secret 粘贴到「Webhook 签名密钥」

**步骤 3：绑定成员飞书 ID（可选但推荐，用于触发 @消息弹窗）**
- 进入「⚙️ 设置 → 成员管理」，为每位成员填写其飞书 `open_id`（形如 `ou_xxxxxxxxxx`）
- 获取方式：
  - 方式一（最简单）：在群里 @某人 后，机器人事件回调 payload 中会包含其 open_id（可借助飞书集成平台调试工具查看）
  - 方式二：飞书管理后台 → 通讯录 → 找到成员 → 导出 open_id
  - 方式三（开发模式）：临时在日历助手配置页提供"接收@消息回调"调试接口（v4 暂不实现，留空则使用纯文本@，消息仍送达群内但不触发个人红点弹窗）
- 未填写 open_id 时，消息中使用普通文本 `@姓名`，群内可见但不会对个人产生强提醒

**步骤 4：设置"日历助手访问地址"（用于消息卡片回跳）**
- 若将本 HTML 文件部署到公司内部 HTTP 服务（如 Nginx、GitHub Pages、飞书云文档附件直链），填写该 URL（如 `https://intranet.example.com/calendar.html`）
- 若本地使用（双击打开 file://），可不填；消息卡片的「查看详情」按钮将复制待办详情链接到剪贴板并提示

**步骤 5：点击「发送测试消息」验证**
- 点击后应在飞书群收到一张测试卡片，点击按钮能正确打开日历助手

#### 4.2.3 消息卡片样式

使用飞书**交互式消息卡片（interactive card）**发送，字段：

```json
{
  "msg_type": "interactive",
  "card": {
    "header": {
      "title": {"tag": "plain_text", "content": "📋 【待办提醒】{title}"},
      "template": "red"
    },
    "elements": [
      {"tag": "div", "text": {"tag": "lark_md", "content": "**📝 描述**：{notes}\n**📅 截止**：{dueDate} {dueTime}\n**👤 负责人**：{atMentions}\n**🔴 优先级**：{priority}\n**🏷️ 状态**：{statusText}"}},
      {"tag": "hr"},
      {"tag": "action", "actions": [
        {"tag": "button", "text": {"tag": "plain_text", "content": "📌 查看详情"}, "type": "primary", "url": "{appBaseUrl}#todo-{todoId}?mention={memberId}"},
        {"tag": "button", "text": {"tag": "plain_text", "content": "📅 加入飞书日程"}, "type": "default", "url": "https://applink.feishu.cn/client/calendar/event/create?summary={encodeURIComponent(title)}&startTime={startUnix}&endTime={endUnix}&attendees={feishuOpenIds}"}
      ]}
    ]
  }
}
```

> **签名校验**：若配置了 secret，按飞书文档生成 HMAC-SHA256 签名放入 `timestamp` 和 `sign` 字段（纯前端使用 CryptoJS 或 Web Crypto API 实现）。

#### 4.2.4 飞书日历深链

「📅 加入飞书日程」按钮使用飞书官方 AppLink 协议，打开飞书日历事件创建页并预填：
- `summary`：待办标题
- `startTime` / `endTime`：截止日期时间前 1 小时（默认 1 小时时长，用户可调整）
- `attendees`：负责人飞书 open_id 列表
- `description`：待办描述+日历助手回跳链接
- 用户在飞书日历中点击"保存"即创建成功，可享受飞书原生日程提醒、弹窗、跨设备同步

#### 4.2.5 通知触发场景

| 场景 | 通知目标 | 卡片标题模板 | 主按钮 |
|------|---------|-------------|--------|
| 新建待办并分配 | 所有 assignees（@）+ 群组 | 📋 新待办分配给你 | 查看详情 / 加入日程 |
| @所有人 | 全部成员所在群 | 📢 全员通知：{title} | 查看详情 |
| 待办即将到期（24h内） | 负责人 | ⏰ 待办即将到期 | 查看详情 |
| 待办已逾期（每日一次） | 负责人 + 其经理 | 🚨 待办已逾期 | 查看详情 |
| 提交成果待审批 | approverId 部门经理 | 🔔 待审批：{title} | 查看并审批 |
| 审批通过 | 负责人 | ✅ 你的任务已通过 | 查看详情 |
| 审批驳回 | 负责人 | ❌ 任务被驳回，请修改 | 查看并修改 |

**防骚扰**：同一待办同一事件 24h 内不重复推送；用户可在设置中关闭"即将到期"或"逾期"提醒。

#### 4.2.6 本地通知 fallback
若未配置 Webhook（离线/不想接飞书），在浏览器支持时使用 `Notification` API 推送系统桌面通知作为兜底。

### 4.3 深链跳转与定位

**URL Hash 协议**：`#todo-{todoId}?mention={memberId}&source=feishu`

页面加载时执行路由逻辑：
1. 解析 `location.hash`
2. 若匹配 `#todo-{id}`：
   a. 查找该待办的截止日期 `dueDate`
   b. 切换日历视图到该日期所在周/月（根据当前视图自动调整焦点）
   c. 在待办列表中找到该待办项，添加 CSS 高亮类（脉冲闪烁 3 秒）
   d. 滚动到该待办项位置（`scrollIntoView({behavior:'smooth', block:'center'})`）
   e. 若有 `mention` 参数，在展开的待办详情中高亮该 @提及位置
   f. 自动打开待办详情面板
3. `source=feishu` 参数：显示一个"来自飞书跳转"小提示条，5 秒后自动消失

### 4.4 成果资料上传

#### 4.4.1 触发时机
- 负责人点击待办的「✅ 标记完成并提交」按钮时，弹出「提交成果」弹窗（而非直接标记完成）
- 若待办无成果要求（创建时可勾选"无需提交成果"），则直接标记为 approved 状态跳过审批

#### 4.4.2 提交成果弹窗
包含：
- **交付结果说明** textarea：必填，简述完成情况
- **成果附件上传区**：
  - 拖拽区域 + 点击选择文件按钮
  - 支持多文件
  - 允许格式：图片（`image/*`）、PDF（`application/pdf`）、Word（`.doc/.docx`）、Excel（`.xls/.xlsx`）、PPT（`.ppt/.pptx`）、Markdown（`.md/.markdown`）、文本（`.txt`）
  - 单文件 ≤ 5MB，总累计 ≤ 20MB（超出显示红色提示，建议删除旧附件）
  - 文件选择后立即转 Base64（`FileReader.readAsDataURL`），显示上传进度条
- **提交**按钮：点击后：
  1. 将 `status` 改为 `submitted`
  2. 填写 `submittedAt`、`deliverables`、`attachments`
  3. 给 approverId 经理发送飞书审批通知
  4. 记录 history

#### 4.4.3 附件展示
- 待办详情中以网格展示附件：
  - 图片显示缩略图，点击放大预览（模态框）
  - 其他文件显示对应文件类型图标 + 文件名 + 大小
  - 每个附件悬停时显示「下载」「删除」按钮（仅上传者或经理可删除）
- 下载：创建 `<a download>` 元素触发 Base64 下载

#### 4.4.4 存储管理
- 设置面板「💾 存储管理」显示 localStorage 已用/总容量
- 提供「清理已通过任务的附件」「导出全部数据」「导入数据」按钮
- 存储配额告警：已用 > 80% 时顶部显示黄色提示条

### 4.5 部门经理审批流

#### 4.5.1 成员-经理映射配置
- 设置「⚙️ → 成员管理」面板：
  - 每个成员卡片有「直属部门经理」下拉（从所有 role=manager 或所有成员中选择）
  - 经理可由任何成员担任（不单独限制 role 字段，但提供「标记为部门经理」checkbox 方便筛选）
  - 支持一键"把某人设为其所在部门所有成员的经理"
- 创建待办选择负责人后，系统自动根据 `members[assignee].managerId` 填入 approverId；若成员无经理，则默认创建者为审批人（或待办创建时手动选）

#### 4.5.2 状态流转

```
    ┌──────────┐  负责人完成并提交   ┌──────────┐  经理通过   ┌──────────┐
    │ pending  │ ─────────────────▶ │ submitted│ ──────────▶ │ approved │
    │ (待处理)  │                    │ (待审批)  │             │ (已通过)  │
    └──────────┘                    └──────────┘             └──────────┘
         ▲                              │
         │                              │ 经理驳回
         │                              ▼
         │                        ┌──────────┐
         └────────────────────────│ rejected │
          负责人修改后重新提交      │ (已驳回)  │
                                  └──────────┘
```

#### 4.5.3 经理审批弹窗
经理点击待审批待办的「审批」按钮打开弹窗，显示：
- 待办原始信息（标题、描述、截止日期、优先级、负责人）
- 交付结果说明
- 成果附件列表（可预览/下载）
- 历史流转记录时间线
- 底部操作：
  - **✅ 通过**：点击二次确认后，status=approved，通知负责人
  - **❌ 驳回**：展开驳回表单：
    - 新要求完成日期（日期选择器，必填）
    - 新增要求/批注（textarea，必填）
    - 确认驳回：status=pending，dueDate 更新为新日期，notes 追加批注，通知负责人

#### 4.5.4 待办列表状态显示
- 待办项左侧根据状态显示不同颜色标记：
  - pending：灰色
  - submitted：橙色（显示"待审批"徽章）
  - approved：绿色（显示"已通过"徽章）
  - rejected：红色（显示"已驳回，DDL 更新至 xx 日"徽章）

### 4.6 筛选与排序

#### 4.6.1 筛选栏新增
顶栏筛选区扩展为：

## 五、安全与限制

1. **数据安全**：所有数据（含附件 Base64、Webhook URL）仅存本地浏览器 localStorage，不上传任何服务器；Webhook 请求直接从浏览器发往飞书官方域名。
2. **CORS 说明**：飞书 Webhook 接口支持跨域浏览器直连（响应不带 `Access-Control-Allow-Origin` 也能发送，因为使用 `mode: 'no-cors'`，但前端无法读取响应；通过"测试消息"按钮以是否实际收到飞书消息判断成功）。
3. **签名密钥**：若配置了签名密钥，使用 Web Crypto API（`crypto.subtle.importKey` + `HMAC-SHA256`）在前端生成签名，密钥留在浏览器。
4. **存储限制**：localStorage 通常 5MB 左右，存储大量 Base64 附件容易超限——设置面板实时显示占用率，>80% 警告，>95% 拒绝新上传。
5. **附件限制**：纯前端方案下附件不会推送到飞书消息中（飞书 Webhook 不支持文件上传），仅在本助手内可查看/下载；消息卡片仅推送文本信息+回跳链接。
6. **跨设备**：单设备使用；如需跨设备，通过设置面板「导出数据/导入数据」手动迁移 JSON 文件。
7. **隐私**：成员的飞书 open_id 仅用于消息 @提及和日历深链参与人字段，不做其他用途。

## 六、不做的事（Out of Scope）

- 不做真实后端/数据库
- 不做飞书 OAuth 登录/扫码登录
- 不做飞书文件云存储/云盘附件
- 不做多人实时协同（CRDT/WebSocket）
- 不做多级审批（v4 仅单级"负责人→经理"）
- 不做代理/委托审批
- 不做 PC 客户端打包（保持 HTML 单文件）
