# 智能日历助手 v4.0 协作汇总版 — 设计文档

日期：2026-09-21
分支：`feature/collab-approval-v4`
基线：main 分支的智能日历助手 v3.0（单文件 HTML + localStorage）

## 一、目标与范围

在现有纯前端单文件 HTML 日历助手基础上，新增以下能力：

1. **@提及系统**：新建待办时支持 @单个成员、@群组、@所有人；@后通过飞书 Webhook 向群发送通知消息并 @对应成员触发其飞书消息弹窗；点击消息可跳转回日历助手并定位到对应 @处。
2. **成果资料上传**：待办完成时上传交付成果，支持图片（所有格式）、PDF、Word、Excel、PPT、Markdown、txt，Base64 存入 localStorage。
3. **部门经理内容汇总**：部门经理可查看所有下属工作的汇总看板（待办进展、已交付成果、逾期预警、按人/职能/时间多维透视），支持一键生成日/周/月报并推送到飞书群。
4. **多维筛选排序**：按人（负责人）、按状态（进行中/已完成/已逾期）、按职能筛选，支持多种排序。
5. **飞书深度联动**：通过群机器人 Webhook 发消息卡片（含飞书日历创建深链+回跳日历助手深链），无需后端即可实现跨端提醒。

**不包含**：真实后端存储、飞书 OAuth 登录、飞书文件云存储、跨设备实时同步、审批通过/驳回流（纯前端 localStorage 单设备方案）。

## 二、整体架构

### 3.4 待办 todos（扩展字段）

```json
{
  "id": "todo-uuid",
  "title": "原字段：标题",
  "notes": "原字段：备注（支持@标记文本解析）",
  "dueDate": "原字段：截止日期",
  "dueTime": "原字段：截止时间",
  "priority": "原字段：优先级",
  "repeat": "原字段：重复",
  "completed": false,
  "categoryId": "原字段：分类",
  "order": 0,
  "createdAt": "...",
  "completedAt": null,

  "assignees": ["m_001", "m_002"],
  "mentionAll": false,
  "mentions": [
    {"memberId": "m_001", "atTime": "ISO时间"}
  ],

  "attachments": [
    {
      "id": "att-uuid",
      "name": "需求文档v2.docx",
      "type": "docx",
      "mime": "application/vnd.openxmlformats-officedocument.wordprocessingml.document",
      "size": 1024000,
      "data": "data:application/vnd.openxmlformats-...;base64,....",
      "uploadedBy": "m_001",
      "uploadedAt": "ISO时间"
    }
  ],

  "deliverables": "",

  "history": [
    {"action": "created", "by": "m_010", "at": "...", "detail": "创建待办并分配"},
    {"action": "completed", "by": "m_001", "at": "...", "detail": "标记完成并提交成果"}
  ]
}
```

**待办状态**（基于原有 `completed` 字段+日期派生，不引入复杂状态机）：
- **进行中**：`completed=false` 且截止日期 >= 今天
- **已完成**：`completed=true`
- **已逾期**：`completed=false` 且截止日期 < 今天
- **即将到期**：`completed=false` 且截止日期在未来 3 天内

## 四、功能模块详细设计

### 4.1 @提及系统

**输入体验**：
- 新建/编辑待办弹窗的「描述」输入框和「负责人」区域支持 `@` 触发联想下拉
- 输入 `@` 后显示下拉列表：① `@所有人` 选项在最顶部；② 最近使用成员；③ 按输入关键字过滤成员和群组
- 键盘上下选择，Enter/Tab 确认
- 群组被选中后，通知时展开为群内所有成员
- 选中后输入框内显示为蓝色标签块（类似飞书 @样式），底层数据以 `@[memberId]` 标记语法存储（如 `请@[m_001]协助@[g_001]`），渲染时解析

**负责人选择区**：
- 弹窗底部独立区域「👥 负责人」，显示已选成员头像+姓名标签，可点×移除
- 快捷按钮：「@所有人」「选择群组」
- 被选中的成员自动成为待办 `assignees`

**展示**：
- 待办列表项右侧显示负责人头像组（最多显示 3 个，更多显示 +N）
- 待办详情中 @姓名高亮为蓝色，hover 显示成员所属部门/职能
- 当前用户（在设置中"当前身份"下拉选择的成员）被@的待办在列表中以左边界彩色条标记

**@所有人**：
- 设置 `mentionAll: true`，通知时展开为 members 列表中除创建者外所有人
- 待办卡片显示 `@所有人` 红色标签

### 4.2 飞书 Webhook 通知集成

#### 4.2.1 配置面板（「⚙️ 设置 → 飞书集成」）

**配置项**：

| 字段 | 说明 | 是否必填 |
|------|------|---------|
| 群机器人 Webhook URL | 飞书群自定义机器人的 webhook 地址 | 是（全局默认） |
| Webhook 签名密钥 | 机器人签名校验 secret，安全校验用 | 推荐 |
| 日历助手访问地址 | 部署后访问本助手的 URL（用于消息卡片回跳链接）；本地双击打开时自动填 `file://` 路径，但建议部署到 http(s) 以支持飞书内直接打开 | 推荐 |
| 当前身份 | 下拉选择「我是哪个成员」，用于识别"我的待办/我的下属汇总" | 是 |
| 每日汇总推送 | 开关：每天 18:00 给经理推送下属当日工作汇总（需页面保持打开） | 可选 |
| 每周汇总推送 | 开关：每周五 17:00 给经理推送周报汇总 | 可选 |

**群组级 Webhook 覆盖**：
- 在「群组管理」中可为每个群组单独配置 Webhook URL，通知该群组待办时发到该群；未配置则使用全局默认。

**测试按钮**：
- 面板内提供「发送测试消息」按钮，验证 Webhook 是否配置正确。

#### 4.2.2 用户配置指引（内置在设置面板中）

设置面板顶部折叠式指引区「📖 如何获取 Webhook？」，点击展开图文步骤：

**步骤 1：创建飞书群自定义机器人**
1. 打开飞书，进入需要接收通知的群聊（或新建一个"日历助手通知群"）
2. 点击群右上角「⋯」→「设置」→「群机器人」→「添加机器人」
3. 选择「自定义机器人」
4. 填写机器人名称：建议填「日历助手」；上传头像（可选）
5. （推荐）安全设置勾选「签名校验」，复制生成的 Sign Secret
6. 点击「添加」，复制生成的 **Webhook 地址**
   - 地址格式：`https://open.feishu.cn/open-apis/bot/v2/hook/xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx`

**步骤 2：填入本面板**
- 将 Webhook 地址粘贴到「群机器人 Webhook URL」
- 若开启了签名校验，将 Sign Secret 粘贴到「Webhook 签名密钥」

**步骤 3：绑定成员飞书 ID（可选但推荐，用于触发 @消息弹窗）**
- 进入「⚙️ 设置 → 成员管理」，为每位成员填写其飞书 `open_id`（形如 `ou_xxxxxxxxxx`）
- 获取方式：
  - 方式一（最简单）：在群里 @某人 后，机器人事件回调 payload 中会包含其 open_id（可借助飞书集成平台调试工具查看）
  - 方式二：飞书管理后台 → 通讯录 → 找到成员 → 导出 open_id
  - 方式三（开发模式）：临时在日历助手配置页提供"接收@消息回调"调试接口（v4 暂不实现，留空则使用纯文本@，消息仍送达群内但不触发个人红点弹窗）
- 未填写 open_id 时，消息中使用普通文本 `@姓名`，群内可见但不会对个人产生强提醒

**步骤 4：设置"日历助手访问地址"（用于消息卡片回跳）**
- 若将本 HTML 文件部署到公司内部 HTTP 服务（如 Nginx、GitHub Pages、飞书云文档附件直链），填写该 URL（如 `https://intranet.example.com/calendar.html`）
- 若本地使用（双击打开 file://），可不填；消息卡片的「查看详情」按钮将复制待办详情链接到剪贴板并提示

**步骤 5：点击「发送测试消息」验证**
- 点击后应在飞书群收到一张测试卡片，点击按钮能正确打开日历助手

#### 4.2.3 消息卡片样式

使用飞书**交互式消息卡片（interactive card）**发送。

**单条待办提醒卡片**：

```json
{
  "msg_type": "interactive",
  "card": {
    "header": {
      "title": {"tag": "plain_text", "content": "📋 【待办提醒】{title}"},
      "template": "red"
    },
    "elements": [
      {"tag": "div", "text": {"tag": "lark_md", "content": "**📝 描述**：{notes}\n**📅 截止**：{dueDate} {dueTime}\n**👤 负责人**：{atMentions}\n**🔴 优先级**：{priority}\n**📊 状态**：{statusText}"}},
      {"tag": "hr"},
      {"tag": "action", "actions": [
        {"tag": "button", "text": {"tag": "plain_text", "content": "📌 查看详情"}, "type": "primary", "url": "{appBaseUrl}#todo-{todoId}?mention={memberId}"},
        {"tag": "button", "text": {"tag": "plain_text", "content": "📅 加入飞书日程"}, "type": "default", "url": "https://applink.feishu.cn/client/calendar/event/create?summary={encodeURIComponent(title)}&startTime={startUnix}&endTime={endUnix}&attendees={feishuOpenIds}"}
      ]}
    ]
  }
}
```

**经理汇总推送卡片**（日报/周报）：

```json
{
  "msg_type": "interactive",
  "card": {
    "header": {
      "title": {"tag": "plain_text", "content": "📊 {period}工作汇总 · {managerName}团队"},
      "template": "blue"
    },
    "elements": [
      {"tag": "div", "text": {"tag": "lark_md", "content": "**📅 统计周期**：{startDate} ~ {endDate}\n**👥 团队人数**：{memberCount} 人\n\n**📈 本周概览**\n✅ 已完成任务：{completedCount} 项\n🔄 进行中：{inProgressCount} 项\n⏰ 即将到期：{dueSoonCount} 项\n🚨 已逾期：{overdueCount} 项\n📎 新提交成果：{newAttachmentCount} 份"}},
      {"tag": "hr"},
      {"tag": "div", "text": {"tag": "lark_md", "content": "**🔴 重点关注（逾期/高优）**\n{highlightsList}"}},
      {"tag": "action", "actions": [
        {"tag": "button", "text": {"tag": "plain_text", "content": "📊 查看完整汇总"}, "type": "primary", "url": "{appBaseUrl}#dashboard?manager={managerId}&period={period}"},
        {"tag": "button", "text": {"tag": "plain_text", "content": "📋 查看全部待办"}, "type": "default", "url": "{appBaseUrl}#list?assignee=subordinates"}
      ]}
    ]
  }
}
```

> **签名校验**：若配置了 secret，按飞书文档使用 Web Crypto API（`crypto.subtle.importKey` + `HMAC-SHA256`）生成签名放入 `timestamp` 和 `sign` 字段。

#### 4.2.4 飞书日历深链

「📅 加入飞书日程」按钮使用飞书官方 AppLink 协议，打开飞书日历事件创建页并预填：
- `summary`：待办标题
- `startTime` / `endTime`：截止日期时间前 1 小时（默认 1 小时时长，用户可调整）
- `attendees`：负责人飞书 open_id 列表
- `description`：待办描述+日历助手回跳链接
- 用户在飞书日历中点击"保存"即创建成功，可享受飞书原生日程提醒、弹窗、跨设备同步

#### 4.2.5 通知触发场景

| 场景 | 通知目标 | 卡片标题模板 | 主按钮 |
|------|---------|-------------|--------|
| 新建待办并分配 | 所有 assignees（@）+ 群组 | 📋 新待办分配给你 | 查看详情 / 加入日程 |
| @所有人 | 全部成员所在群 | 📢 全员通知：{title} | 查看详情 |
| 待办即将到期（24h内） | 负责人 | ⏰ 待办即将到期 | 查看详情 |
| 待办已逾期（每日一次） | 负责人 + 其经理 | 🚨 待办已逾期 | 查看详情 |
| 成员提交成果 | 该成员直属经理 | 📎 {name}提交了新成果 | 查看成果 |
| 日报推送（每日18:00） | 经理 | 📊 今日团队工作汇总 | 查看完整汇总 |
| 周报推送（每周五17:00） | 经理 | 📊 本周团队工作汇总 | 查看完整汇总 |

**防骚扰**：同一待办同一事件 24h 内不重复推送；用户可在设置中关闭各类提醒。

#### 4.2.6 本地通知 fallback
若未配置 Webhook（离线/不想接飞书），在浏览器支持时使用 `Notification` API 推送系统桌面通知作为兜底。

### 4.3 深链跳转与定位

**URL Hash 协议**：
- 单条待办：`#todo-{todoId}?mention={memberId}&source=feishu`
- 经理汇总：`#dashboard?manager={managerId}&period={day|week|month}`
- 列表筛选：`#list?assignee={memberId|subordinates}&status={progress|done|overdue}&func={funcId}`

页面加载时执行路由逻辑：
1. 解析 `location.hash`
2. 若匹配 `#todo-{id}`：
   a. 查找该待办的截止日期 `dueDate`
   b. 切换日历视图到该日期所在周/月（根据当前视图自动调整焦点）
   c. 在待办列表中找到该待办项，添加 CSS 高亮类（脉冲闪烁 3 秒）
   d. 滚动到该待办项位置（`scrollIntoView({behavior:'smooth', block:'center'})`）
   e. 若有 `mention` 参数，在展开的待办详情中高亮该 @提及位置
   f. 自动打开待办详情面板
3. 若匹配 `#dashboard`：直接切换到经理汇总仪表盘视图
4. 若匹配 `#list`：应用对应的筛选条件
5. `source=feishu` 参数：显示一个"来自飞书跳转"小提示条，5 秒后自动消失

### 4.4 成果资料上传

#### 4.4.1 触发时机
- 负责人点击待办的「✅ 标记完成」按钮时，弹出「提交成果」弹窗
- 若待办无成果要求（创建时勾选了"完成时无需提交成果"），直接标记完成，跳过附件上传
- 完成后待办仍可补充上传附件（在详情面板点击「📎 添加成果」）

#### 4.4.2 提交成果弹窗
包含：
- **交付结果说明** textarea：可选（简单任务可不填），简述完成情况
- **成果附件上传区**：
  - 拖拽区域 + 点击选择文件按钮
  - 支持多文件
  - 允许格式：图片（`image/*`）、PDF（`application/pdf`）、Word（`.doc/.docx`）、Excel（`.xls/.xlsx`）、PPT（`.ppt/.pptx`）、Markdown（`.md/.markdown`）、文本（`.txt`）
  - 单文件 ≤ 5MB，总累计 ≤ 20MB（超出显示红色提示，建议删除旧附件）
  - 文件选择后立即转 Base64（`FileReader.readAsDataURL`），显示上传进度条
- **✅ 确认完成**按钮：点击后：
  1. 将 `completed` 设为 `true`，记录 `completedAt`
  2. 保存 `deliverables`、`attachments`
  3. 给该成员的直属经理发送飞书"新成果提交"通知
  4. 记录 history

#### 4.4.3 附件展示
- 待办详情中以网格展示附件：
  - 图片显示缩略图，点击放大预览（模态框）
  - 其他文件显示对应文件类型图标 + 文件名 + 大小 + 上传时间
  - 每个附件悬停时显示「下载」「删除」按钮（仅上传者或其经理可删除）
- 下载：创建 `<a download>` 元素触发 Base64 下载
- 经理在汇总看板中可直接查看下属所有成果附件

#### 4.4.4 存储管理
- 设置面板「💾 存储管理」显示 localStorage 已用/总容量
- 提供「清理30天前已完成任务的附件」「导出全部数据」「导入数据」按钮
- 存储配额告警：已用 > 80% 时顶部显示黄色提示条

### 4.5 部门经理内容汇总看板

#### 4.5.1 成员-经理映射配置
- 设置「⚙️ → 成员管理」面板：
  - 每个成员卡片有「直属部门经理」下拉（从所有 role=manager 的成员中选择）

#### 4.5.6 自动定时推送

## 五、安全与限制

1. **数据安全**：所有数据（含附件 Base64、Webhook URL）仅存本地浏览器 localStorage，不上传任何服务器；Webhook 请求直接从浏览器发往飞书官方域名。
2. **CORS 说明**：飞书 Webhook 接口支持跨域浏览器直连（使用 `mode: 'no-cors'` 发送，前端无法读取响应；通过"测试消息"按钮以是否实际收到飞书消息判断成功）。
3. **签名密钥**：若配置了签名密钥，使用 Web Crypto API 在前端生成签名，密钥留在浏览器。
4. **存储限制**：localStorage 通常 5MB 左右，存储大量 Base64 附件容易超限——设置面板实时显示占用率，>80% 警告，>95% 拒绝新上传。
5. **附件限制**：纯前端方案下附件不会推送到飞书消息中（飞书 Webhook 不支持文件上传），仅在本助手内可查看/下载；消息卡片仅推送文本信息+回跳链接。
6. **定时推送限制**：汇总推送依赖页面在浏览器中打开，关闭后无法触发（纯前端无后台进程限制）。
7. **跨设备**：单设备使用；如需跨设备，通过设置面板「导出数据/导入数据」手动迁移 JSON 文件。
8. **隐私**：成员的飞书 open_id 仅用于消息 @提及和日历深链参与人字段，不做其他用途。

## 六、不做的事（Out of Scope）

- 不做真实后端/数据库
- 不做飞书 OAuth 登录/扫码登录
- 不做飞书文件云存储/云盘附件
- 不做多人实时协同（CRDT/WebSocket）
- **不做审批通过/驳回流程**（v4 改为经理汇总视角，成员自行完成任务并提交成果，经理查看汇总）
- 不做代理/委托
- 不做 PC 客户端打包（保持 HTML 单文件）

## 七、版本与迁移

- 数据版本 `version: 4`
- 首次打开 v4 时自动迁移 v3 数据：为所有旧 todo 补全新字段默认值（assignees=[]、mentionAll=false、mentions=[]、attachments=[]、deliverables=''、history=[原created事件+completed事件]等）
- 若旧数据中 `completed=true`，补写一条 completed history
- 迁移前自动在 localStorage 备份 `calendarAssistantData_v3_backup`
